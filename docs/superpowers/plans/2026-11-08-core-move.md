# Core Move (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every decision the TUI holds into `zrush-core`, so a second interface can be written on top of it, then ship that as the CLI release `v0.0.4`, which also understands the coming `cli-v*` tags.

**Architecture:** `crates/zrush` keeps drawing, keys, modals and the `:` command language; everything that loads data, decides what a row means, asks a question or carries out an action moves to `crates/zrush-core`. Each task leaves the TUI behaving exactly as before: the existing TUI tests (unit, `tests/cli.rs`, `tests/pty.rs`, `tests/readme.rs`) are the behaviour proof and must pass unchanged unless a step says otherwise.

**Tech Stack:** Rust 2024, MSRV 1.99, ratatui/crossterm (TUI only), nucleo-matcher (moves to core), std threads + `mpsc`.

**Spec:** `docs/superpowers/specs/2026-11-08-zrush-gui-design.md` (Phase 1, Release sequence, Distribution).

## Global Constraints

- `unsafe_code = "forbid"`; clippy pedantic with `-D warnings`; `unwrap`/`expect` denied outside tests. Every crate keeps `[lints] workspace = true`.
- MSRV `1.99` (`rust-version` in `Cargo.toml`); dependencies declared once in `[workspace.dependencies]`.
- License GPL-3.0-only; `cargo deny check` must pass (`deny.toml`).
- `zrush-core` never depends on ratatui, crossterm or clap.
- User-visible strings (flash lines, modal titles, bodies, choice labels) are kept byte-for-byte: tests assert on them.
- Done for each task = `./check` prints `all green`.
- Commits: conventional (`refactor(core): …`, `fix(core): …`, `feat(update): …`, `chore: …`), one per task at least.

## Review Focus

1. A TUI and a GUI open on the same `config.toml`, each saving a different setting: both changes survive, and an env override (`ZRUSH_EDITOR`) is never written into the file — Task 1.
2. A conversation turn holding Markdown (paragraphs, a fenced code block, a list) keeps its line breaks in core, while the TUI preview still wraps it as one flowing text — Task 2.
3. A tab or window closes while its probes are running: the loader's threads stop sending and nothing panics — Task 6.
4. An orphan whose old path is unknown is never offered "Recreate its worktree"; a misfiled live session is never asked about — Task 9.
5. The CLI updater handed a `gui-v*` tag, or any other prefix, offers nothing — Task 10.
